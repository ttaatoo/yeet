---
title: What Yeet is
description: A native macOS terminal workspace — projects, sessions, browsers, files, git, and coding agents in one window.
---

Yeet is a terminal. The rest of the window exists so you don't have to leave it.

Each repository you work on becomes a **project** in the sidebar. A project holds
as many terminal **sessions** as you need, each one a tab with its own directory
and scrollback, and each tab can be **split** into panes. Beside all of that sit
the side panels, each one a keystroke away: a git panel for reviewing and
committing, a file tree with an editor, and a live view of the processes and
ports your session is running. Browser panes and coding-agent status live in
the same project layout instead of becoming separate windows to manage.

Terminal panes use a native, GPU-accelerated [Alacritty](/docs/terminal) backend.
Your shell, prompt, aliases, and dotfiles are untouched.

![Yeet showing a project's terminal session with the git panel open](/yeet-screenshot.png)

## What it is not

Yeet is not an IDE, and it's not trying to become one. The git and files panels
exist so you can read a diff or fix a typo without switching apps — not so you
can live in them. Nothing runs behind your back: every git action maps to a
command you could have typed, and the output is shown to you.

## Free, and quiet about it

Yeet is free and open source (GPLv3), with no account and no subscription. The
app and this site send no telemetry and collect no analytics. Packaged Yeet has
no Sparkle feed and does not check for updates on its own; build from source,
or use Homebrew / a GitHub Release zip when that asset exists. Browser
navigation and agent CLIs make the requests you explicitly ask them to make.
