Most persistent Yeet settings live in one file:

```
~/.config/yeet/config.toml
```

Debug builds use `~/.config/yeet-dev/config.toml`. If the Yeet directory is
missing, leftover `~/.config/kerox` (then older `~/.config/kero`) is copied in.

The Settings window (<kbd>Cmd</kbd>+<kbd>,</kbd>) writes this same file. A few
macOS-owned settings—language and automatic updates—live elsewhere and are
listed at the end of this page.

## How the file behaves

Worth knowing before you hand-edit:

- **It's read at launch.** Editing the file while Yeet is running changes
  nothing until you relaunch. Changes made in Settings apply immediately,
  except where the control says otherwise.
- **Yeet rewrites it whenever a file-backed setting changes.** The file is
  regenerated from scratch, so your comments and unknown keys are lost the
  next time you use one of those controls. Pick one editor for the file, or
  keep an authoritative copy in your dotfiles.
- **Only non-default values are written, with one exception.** `font-size` is
  always present. Deleting any other key restores its default.
- **The parser is deliberately small.** It supports flat keys, dotted keys,
  `[table]` headers, `#` comments, and string/number/boolean values. It does not
  support arrays, inline tables, or multi-line strings.
- **Bad values fall back safely.** An out-of-range size, unknown theme, or
  misspelled theme does not stop Yeet from launching.

## Appearance

### `theme`

`"system"` · `"light"` · `"dark"` — default `"system"`

Chooses the app appearance. `"system"` follows macOS; the other two pin Yeet
to one appearance.

### `theme-dark` and `theme-light`

string — defaults `"Yeet Dark"` and `"Yeet Light"`

The color theme for each appearance. A theme recolors terminal panes, the
editor, and diffs. Dark chrome (the project list and the Files/Git inspector)
is a solid warm near-black panel one step lighter than the terminal canvas,
so the two sidebars match after a swap. Light chrome stays a solid panel from
the selected light theme. `"Default Dark"` and `"Default Light"` still resolve
to Yeet Dark and Yeet Light. The selected-project stripe and agent indicator
follow `chrome-accent`, not the catalog theme.

Settings lists the curated theme catalog. A hand-written name must match one
of those display names exactly, including case, or Yeet falls back to the
corresponding default.

### `chrome-accent`

`"coral"` · `"vivid-purple"` — default `"coral"`

The window-chrome accent family in Settings → Colors → Accent. Coral is the
mascot orange and mint. Vivid Purple uses a bright purple stripe and a green
indicator; blocked agents stay coral-red so they do not match the selected
stripe. This does not change terminal palettes or cursor colors.

Omitted when Coral. An unknown value falls back to Coral.

### `toolbar.visibility`

`"hide"` · `"auto"` · `"always"` — default `"hide"`

Controls the compact toolbar below the active tab:

- `"hide"` keeps it out of the window.
- `"auto"` shows it only when the project directory is a Git repository.
- `"always"` keeps its Git entry point visible in every project, including a
  **No Git Repository** state.

See [The Git toolbar](/docs/git#the-git-toolbar) for what it shows.

### `layout.swap-sidebars`

boolean — default `false`

When true, the Files, Git, and Info inspector sits on the left and the project
list on the right. <kbd>Cmd</kbd>+<kbd>B</kbd> still toggles the project
sidebar and <kbd>Cmd</kbd>+<kbd>Shift</kbd>+<kbd>B</kbd> still toggles the
inspector; each panel keeps its own width. Traffic lights stay at the window's
top-leading corner.

## Text

### `font-family`

string — default `""`, meaning the bundled JetBrains Mono

The terminal, editor, and diff viewer share this family. Give a family name,
not a face: `"IBM Plex Mono"`, not `"IBM Plex Mono Regular"`. Unknown or
non-monospace families fall back to the bundled default.

Yeet also attaches Symbols Nerd Font as a fallback, so Powerline separators
and icon glyphs work even when the chosen family is not a patched Nerd Font.

### `font-size`

number, 8–32 — default `13`

The shared terminal, editor, and diff font size in points. This is the one key
Yeet writes even when it has the default value.

### `sidebar.font-size`

number, 9–18 — default `14`

The base text size for the project sidebar and the Git/Info inspector. Section
headings, rows, metadata, and controls keep their relative hierarchy as the
base changes. File names in the Files tree use
[`files.font-size`](#filesfont-size).

### `files.font-family`

string — default `""`, meaning the system UI font

The family for file names in the Files inspector. Empty keeps the macOS UI
font. Settings lists the same families as the terminal Font section, including
bundled JetBrains Mono.

### `files.font-size`

number, 9–22 — default `11.5`

The file-name size in the Files inspector, in points. Badges, disclosure
chevrons, and metadata stay smaller than the name as this changes. The default
matches the previous look at the default sidebar scale.

### `terminal.font-thicken`

boolean — default `false`

Renders terminal glyphs with slightly heavier strokes, similar to classic
macOS font smoothing. The Settings preview shows the result. Older
`font-thicken` configs are still read, then rewritten using the current dotted
key.

### `editor.wrap-lines`

boolean — default `false`

Soft-wraps long lines to the pane width in the [file editor](/docs/files).
When false, long lines scroll horizontally. It does not change wrapping in a
terminal or diff.

## Terminal

### `clipboard-write`

`"ask"` · `"allow"` · `"deny"` — default `"allow"`

What happens when a terminal program copies text with `OSC 52` (vim, tmux,
coding agents). `"allow"` writes the macOS clipboard immediately. `"ask"` shows
the confirmation dialog. `"deny"` ignores the copy. The dialog's **Always
Allow** button stores `"allow"`.

### `clipboard-read`

`"ask"` · `"allow"` · `"deny"` — default `"ask"`

What happens when a terminal program requests the macOS clipboard with
`OSC 52`, including over SSH. `"ask"` confirms first so a remote host cannot
read the clipboard silently. `"allow"` returns it immediately. `"deny"`
returns nothing.

### `terminal.macos-option-as-alt`

boolean — default `false`

When true, Option-key combinations are sent to terminal programs as Alt/Meta
shortcuts. The default leaves Option with the active macOS input source so
layouts such as Polish Pro can type their composed characters.

### `terminal.restore-history`

boolean — default `false`

Restores each terminal's previous scrollback above a fresh shell after a
relaunch. The restored content is static text, not a surviving process.

Restored scrollback is stored on disk, so any secrets shown in the terminal may
be included. This setting is off by default.
[Projects, tabs, and pane layout](/docs/projects#what-survives-a-relaunch) are
restored either way.

## Automation

### `ai.enabled`

boolean — default `false`

Lets supported coding agents coordinate background Yeet panes when you ask in
plain language, and shows provider-reported lifecycle status in the UI. Yeet
does not infer status from terminal text. The Settings toggle is the recommended
way to change it because errors are shown inline and conflicting existing setups
are left untouched.

The human workflow is described in
[Working with AI agents](/docs/automation).

## A complete example

```toml title="~/.config/yeet/config.toml"
theme = "dark"
theme-dark = "Catppuccin Mocha"
theme-light = "Catppuccin Latte"
chrome-accent = "vivid-purple"
font-family = "IBM Plex Mono"
font-size = 14
sidebar.font-size = 13
files.font-family = "JetBrains Mono"
files.font-size = 13
toolbar.visibility = "auto"
layout.swap-sidebars = true
terminal.font-thicken = true
terminal.macos-option-as-alt = false
terminal.restore-history = true
editor.wrap-lines = true
ai.enabled = true
```

Every key is optional. Delete a key to return that setting to its default.

## Settings outside this file

- **Language.** Settings offers System Default, English, Simplified Chinese,
  and Japanese. The choice uses macOS's per-app language preference and needs a
  relaunch, so it lives in Yeet's preferences rather than TOML.
- **Automatic update checks.** Packaged Yeet has no Sparkle feed, so Settings
  does not show update controls. Rebuild from source, or use Homebrew / a
  GitHub Release zip when that asset exists.
- **Window and layout state.** Window size, sidebar widths, selected panels,
  projects, tabs, panes, browser URLs, and diff control preferences live in
  Yeet's macOS preferences and session snapshot.
- **Keybindings.** The [shortcuts](/docs/shortcuts) are fixed for now.
